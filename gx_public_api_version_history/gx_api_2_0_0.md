# Glasses X API specification

**Version:** 2.0.0

Remote API for the Tobii Glasses X application. Use it to control recordings, check device status, stream live view, and track upload progress.

## Properties

|Name|Type|Access|Description|
|-|-|-|-|
|api.version|string|read|Returns the API version.|
|glasses.serial_number|string|read|Returns the serial number of the connected glasses. Returns an empty string if no glasses are connected.|
|recorder.current.id|string|read|Returns the ID of the current recording. Returns an empty string if no recording is in progress.|
|recorder.current.name|string|read|Returns the name of the current recording. Returns an empty string if no recording is in progress.|
|recorder.current.duration_seconds|integer|read|Returns the duration of the current recording, in seconds. Returns 0 if no recording is in progress.|
|glasses.audio.is_enabled|boolean|read|Reports whether audio is enabled for live view and recording.|

## Signals

|Name|Payload type|Emits on subscribe|Description|Details|
|-|-|-|-|-|
|glasses.is_connected|boolean|yes|Emits the current connection state of the glasses.|-|
|live_viewer.ice_candidate.discovered|record|no|Emits an ICE candidate generated by the app for the active live view session.|[details](#signal-live-viewer-ice-candidate-discovered-payload)|
|live_viewer.is_streaming|boolean|yes|Emits the current live view streaming state.|-|
|recorder.is_recording|boolean|yes|Emits the current recording state.|-|
|uploader.progress.changed|record|no|Emits an update when a recording upload changes state.|[details](#signal-uploader-progress-changed-payload)|

## Actions

Action requests use an ordered `args` array. Arguments are positional and must be sent in the documented order.

|Name|Arguments|Returns|Description|Details|
|-|-|-|-|-|
|api.ping|none|string|Returns `pong`.|-|
|recorder.start|name?: string, project_id?: string|string|Starts a recording by using the same flow as the app UI. If provided, `project_id` is stored and used for upload routing in the active workspace.|-|
|recorder.stop|none|record|Stops the current recording by using the same flow as the app UI and returns summary metadata for the saved recording.|[details](#action-recorder-stop-types)|
|live_viewer.session.create|ice_servers?: array<object>|boolean|Creates a WebRTC live view session. The API supports one session at a time. If a session is already active, this action reuses it.|[details](#action-live-viewer-session-create-types)|
|live_viewer.offer.create|none|string (optional)|Creates an SDP offer for the active live view session.|-|
|live_viewer.ice_candidate.add|index: integer, candidate: string|void|Adds a client ICE candidate to the active live view session.|-|
|live_viewer.session.start|answer: string|boolean|Starts live view streaming by applying the provided SDP answer to the active session.|-|
|live_viewer.session.delete|none|void|Deletes the active live view session, if one exists.|-|

## Error codes

Every error response includes a `code` field with one of the stable identifiers below. New codes may be added; clients should treat unrecognized codes as generic errors.

|Code|
|-|
|`invalid_payload`|
|`invalid_request_type`|
|`unknown_property`|
|`unknown_signal`|
|`unknown_action`|
|`unknown_signal_id`|
|`invalid_args`|
|`action_failed`|
|`internal_error`|

## Type details

<a id="signal-live-viewer-ice-candidate-discovered-payload"></a>

### Signal live_viewer.ice_candidate.discovered payload

Emits an ICE candidate generated by the app for the active live view session.

Wire format: Payload values are encoded as an ordered JSON array. The field names below map to array positions in order.

**Payload fields**

|Name|Type|Description|
|-|-|-|
|sdp_m_line_index|integer|The index of the related m-line in the SDP.|
|candidate|string|The ICE candidate string generated by the app.|

<a id="signal-uploader-progress-changed-payload"></a>

### Signal uploader.progress.changed payload

Emits an update when a recording upload changes state.

Wire format: Payload values are encoded as an ordered JSON array. The field names below map to array positions in order.

**Payload fields**

|Name|Type|Description|
|-|-|-|
|recording_id|string|The ID of the local recording.|
|hub_recording_id|string|The backend recording ID for this upload. Empty until available.|
|state|string|The current upload state.|
|updated_at|string|The UTC timestamp, in ISO 8601 format, of the latest upload state change.|

<a id="action-recorder-stop-types"></a>

### Action recorder.stop types

Stops the current recording by using the same flow as the app UI and returns summary metadata for the saved recording.

**Arguments**

*No arguments.*

**Returns**

* **Type:** record
* **Required:** yes
* **Description:** Summary metadata for the saved recording. This matches the completion information shown in the app.

Wire format: Return values are encoded as an ordered JSON array. The field names below map to array positions in order.

**Return fields**

|Name|Type|Description|
|-|-|-|
|recording_id|string|The ID of the saved recording.|
|gaze_percentage|float|The percentage of gaze samples that were valid in the saved recording.|
|gaze_samples|integer|Total number of gaze samples collected in the recording.|
|valid_gaze_samples|integer|The number of valid gaze samples in the saved recording.|
|duration_milliseconds|integer|The recording duration, in milliseconds.|

<a id="action-live-viewer-session-create-types"></a>

### Action live_viewer.session.create types

Creates a WebRTC live view session. The API supports one session at a time. If a session is already active, this action reuses it.

**Arguments**

|Name|Type|Required|Description|
|-|-|-|-|
|ice_servers|array<object> (optional)|no|Optional list of ICE servers for the live view session.|


**`ice_servers` item fields**

|Field|Type|Required|Description|
|-|-|-|-|
|credential|string (optional)|no||
|urls|array<string>|yes||
|username|string (optional)|no||

**Returns**

* **Type:** boolean
* **Required:** yes
* **Description:** Returns `true` if the session is created or an active session is reused. Returns `false` if session creation fails.
