# Glasses X Application Recording Format Guide

This guide describes the files that the Glasses X application saves for a recording in **Local control** mode, and how to read them in Python.



##### How to use this guide

1. Find the recording folder and copy it to your computer.
2. Use the file table to identify each file and its protobuf message type.
3. Read the protobuf files with the Python reader.
4. Use the message reference for the meaning, unit, and validity of each field.

To start and stop recordings from your own client, see the [Glasses X Application Public API Guide](GX_App_Public_API_Guide.md).



### Find the recording

The Glasses X application saves recordings on the device only when it uses **Local control**. With **Cloud access**, the application uploads recordings to Tobii Discovery Hub and does not keep them on the device.

With **Local control**, the application saves each recording in this folder, in the internal storage of the device:

```text
Documents/TobiiGlassesX/<recording name>/
```

If a folder with the same name exists, the application adds a number, for example `My Recording (2)`.

To copy a recording to a computer, do one of these steps:

* Connect the device to the computer with USB, and copy the folder.
* Use **Share recording** in the Glasses X application. **Share recording** creates a ZIP file that contains the recording folder. Extract the ZIP file before you read the recording.



### Recording contents

Each recording folder contains the scene video, a metadata file, the protobuf schema, and one protobuf file for each data stream. All files are at the top level of the folder.

|File|Contents|Protobuf message type|
|-|-|-|
|`scenevideo.mp4`|Scene camera video. It also contains audio if **Record audio** was selected before the recording started.|Not protobuf|
|`recording.json`|Recording metadata, such as the name, duration, and glasses and device information. Its format can change between releases and is not described in this guide.|Not protobuf|
|`glassesdata.proto`|Schema for the protobuf files in this recording|Not data|
|`gaze2d.pb.gz`|Gaze point in the scene camera image|[`Gaze2D`](#gaze2d)|
|`gaze3d.pb.gz`|Per-eye and combined 3D gaze data|[`Gaze3D`](#gaze3d)|
|`accelerometergyro.pb.gz`|Glasses IMU acceleration and angular velocity|[`AccelerometerGyro`](#accelerometergyro)|
|`magnetometer.pb.gz`|Glasses IMU magnetic field|[`Magnetometer`](#magnetometer)|
|`scenecameradata.pb.gz`|Scene camera exposure and gain settings|[`SceneCameraData`](#scenecameradata)|
|`glassesevents.pb.gz`|Recording events|[`GlassesEvent`](#glassesevent)|
|`utcmapping.pb.gz`|Mapping between recording time and UTC|[`UtcTimeMapping`](#utctimemapping)|
|`geographiccoordinates.pb.gz`|Location of the device|[`GeographicalCoordinates`](#geographicalcoordinates)|

The `glassesdata.proto` file in a recording is the source of truth for the messages in that recording. Use it to read that recording.

A stream can contain no messages when its data source was not available or did not produce samples. Readers must also accept that a file is absent.



### Read the recording

##### Prerequisites

* [Python](https://www.python.org/downloads/) 3.10 or later
* The Protocol Buffers compiler, `protoc`, from the [Protocol Buffers v3.20.3 release](https://github.com/protocolbuffers/protobuf/releases/tag/v3.20.3)
* The [`protobuf` 3.20 Python package](https://pypi.org/project/protobuf/3.20.3/)

Use `protobuf` 3.20. A newer `protobuf` package can be incompatible with code generated by an older `protoc`.



##### File encoding

Each `.pb.gz` file is a gzip-compressed sequence of protobuf messages. It is not a single protobuf message or a protobuf `repeated` field.

* A varint-encoded byte length comes before each message. This is the standard *delimited* protobuf format.
* All messages in one file have the type in the file table.

Decompress the file, then read one length prefix and one message at a time. This lets you stream large recordings without loading a full file into memory.



##### Generate the Python bindings

From the recording folder, generate the bindings from the schema in that recording:

```bash
protoc --python_out=. glassesdata.proto
```

This creates `glassesdata_pb2.py`.



##### Reader

Save this reader as `read_recording.py`, next to `glassesdata_pb2.py`. It uses only the Python standard library and the generated bindings.

```python
import gzip
from pathlib import Path
from typing import Iterator, Optional, Type

from google.protobuf.message import Message


def read_varint32(stream) -> Optional[int]:
    """Read one protobuf length prefix; return None only at a clean EOF."""
    value = 0
    for shift in range(0, 35, 7):
        byte = stream.read(1)
        if not byte:
            if shift == 0:
                return None
            raise EOFError("truncated protobuf length prefix")
        value |= (byte[0] & 0x7F) << shift
        if not byte[0] & 0x80:
            return value
    raise ValueError("invalid protobuf length prefix")


def iter_delimited_messages(
    path: str | Path, message_type: Type[Message], max_message_size: int = 64 * 1024 * 1024
) -> Iterator[Message]:
    """Yield the gzip-compressed, length-delimited messages in *path*."""
    with gzip.open(path, "rb") as stream:
        while True:
            size = read_varint32(stream)
            if size is None:
                return
            if size > max_message_size:
                raise ValueError(f"message is unexpectedly large: {size} bytes")
            payload = stream.read(size)
            if len(payload) != size:
                raise EOFError("truncated protobuf message")
            message = message_type()
            message.ParseFromString(payload)
            yield message
```



###### Example

Print valid 2D gaze samples:

```python
from glassesdata_pb2 import Gaze2D
from read_recording import iter_delimited_messages

for sample in iter_delimited_messages("gaze2d.pb.gz", Gaze2D):
    if sample.valid:
        print(sample.timestamp_us, sample.gaze.x, sample.gaze.y)
```

To read another file, change the file name and the message type to a pair from the file table.



##### Reader rules

* Select the message type from the file table. A protobuf parser cannot find the type from the binary data.
* If the gzip data is malformed, or a length prefix or message is incomplete, treat the recording as corrupted or incomplete. Do not treat a partial last message as a normal end of file.
* Keep timestamps as 64-bit integers. Microseconds converted to floating point lose precision in long recordings.
* Ignore unknown protobuf fields. This lets your reader process recordings that contain new fields.



### Timestamps

Sample and event timestamps named `timestamp_us` are integer microseconds in recording time. Recording time comes from a monotonic clock on the device that runs the Glasses X application. It is not a Unix timestamp.

The `frame_dropped` event is an exception. Its timestamps are on the MP4 timeline. See [EventFrameDropped](#eventframedropped).

Use the timestamps to order and correlate the protobuf streams. The sample rates are nominal, so do not calculate a sample time from its index.



##### Align data with the video

The MP4 timeline starts at zero at the first saved scene video frame. The `collecting_started` event in `glassesevents.pb.gz` gives the recording time of that frame.

The MP4 presentation time of each video frame is its recording time minus the `collecting_started` time. To get the recording time of a frame, add the two values:

```python
recording_timestamp_us = collecting_started_timestamp_us + round(video_time_seconds * 1_000_000)
```

The MP4 file stores video time in units of 1/90000 s. The recording time of a frame can be up to 11 µs after the calculated value. This error does not increase during the recording.

The recording time of a frame is the time when the glasses' processor received the frame from the camera sensor, converted to the device clock. It is not the time when the device received the frame, and not the middle of the exposure.

Use the presentation time of each frame from the MP4 file. Do not assume a constant frame rate. For example, [FFprobe](https://ffmpeg.org/ffprobe.html) prints the presentation time of each video frame in seconds:

```bash
ffprobe -v error -select_streams v:0 -show_entries packet=pts_time -of csv=p=0 scenevideo.mp4
```



###### Example

Find the nearest valid 2D gaze sample for each video frame. The example skips a frame when no valid sample is within 20 ms of it.

```python
import bisect
import subprocess

from glassesdata_pb2 import Gaze2D, GlassesEvent
from read_recording import iter_delimited_messages

MAX_DISTANCE_US = 20_000

started_us = next(
    event.timestamp_us
    for event in iter_delimited_messages("glassesevents.pb.gz", GlassesEvent)
    if event.WhichOneof("event") == "collecting_started"
)

gaze = [sample for sample in iter_delimited_messages("gaze2d.pb.gz", Gaze2D) if sample.valid]
gaze_times = [sample.timestamp_us for sample in gaze]

ffprobe = subprocess.run(
    ["ffprobe", "-v", "error", "-select_streams", "v:0", "-show_entries", "packet=pts_time",
     "-of", "csv=p=0", "scenevideo.mp4"],
    capture_output=True, text=True, check=True,
)
video_times = sorted(float(line) for line in ffprobe.stdout.split())

for frame_index, video_time_seconds in enumerate(video_times):
    frame_us = started_us + round(video_time_seconds * 1_000_000)
    i = bisect.bisect_left(gaze_times, frame_us)
    candidates = gaze[max(i - 1, 0):i + 1]
    if not candidates:
        continue
    nearest = min(candidates, key=lambda sample: abs(sample.timestamp_us - frame_us))
    if abs(nearest.timestamp_us - frame_us) <= MAX_DISTANCE_US:
        print(frame_index, nearest.gaze.x, nearest.gaze.y)
```



##### Convert to UTC

`utcmapping.pb.gz` contains two pairs of recording time and UTC time: one from when the recording starts, and one from when it stops.

To convert a recording time to UTC, interpolate linearly between the two pairs:

```python
utc_us = start.utc_unix_epoch_us + (
    (timestamp_us - start.timestamp_us)
    * (stop.utc_unix_epoch_us - start.utc_unix_epoch_us)
    // (stop.timestamp_us - start.timestamp_us)
)
```



### Message reference

`Point2D` has the float fields `x` and `y`. `Point3D` and `Vector3D` have the float fields `x`, `y`, and `z`.



##### Default values and optional fields

Protocol Buffers version 3 does not store a field that has its default value, such as `0`, `0.0`, `false`, or an empty string. When you read such a field, you get the default value. You cannot tell whether the application set the field to the default value or did not set it.

A default value does not mean that a measurement is valid. Each `*_valid` field tells whether the field with the same name prefix is valid. Read it before you use the value.



###### Optional fields

Fields marked `optional` in `glassesdata.proto` record whether they were set. Use `HasField()` to check:

```python
if sample.left.HasField("blink"):
    print(sample.left.blink)
```

An optional field that is not set reads as its default value. Call `HasField()` only for `optional` fields and message fields. For other fields, it raises `ValueError`.



###### Printing and converting messages

Tools that print or convert messages leave out fields that have their default value. For example, `print(message)` and `MessageToDict()` do not show a non-optional `valid` field that is `false`. They show an optional field when it is set, even to its default value.

To include all fields in a dictionary or JSON, add this argument:

```python
from google.protobuf.json_format import MessageToDict

MessageToDict(message, preserving_proto_field_name=True, including_default_value_fields=True)
```

In `protobuf` 5.26 and later, the argument is named `always_print_fields_with_no_presence`. Optional fields that are not set stay left out.

`MessageToDict()` and `MessageToJson()` give 64-bit integers, such as `timestamp_us`, as strings. Convert them with `int()`.



<a id="gaze2d"></a>

##### Gaze2D

File: `gaze2d.pb.gz`. One message for each gaze sample, valid or not.

|Field|Type|Unit|Description|
|-|-|-|-|
|`timestamp_us`|int64|µs|Recording time of the sample.|
|`gaze`|Point2D|normalized|Gaze point in the scene camera image. `(0.0, 0.0)` is the top-left corner and `(1.0, 1.0)` is the bottom-right corner.|
|`valid`|bool|-|If `false`, `gaze` is `(0.0, 0.0)` and has no meaning.|



<a id="gaze3d"></a>

##### Gaze3D

File: `gaze3d.pb.gz`. One message for each gaze sample, with the same timestamps as `gaze2d.pb.gz`.

|Field|Type|Unit|Description|
|-|-|-|-|
|`timestamp_us`|int64|µs|Recording time of the sample.|
|`left`, `right`|[Eye](#eye)|-|Data for the left eye and the right eye.|
|`gaze_origin_combined_mm`|Point3D|mm|Combined gaze origin of both eyes.|
|`gaze_direction_combined_normalized`|Vector3D|unit vector|Combined gaze direction of both eyes.|
|`convergence_point_mm`|Point3D|mm|The point 1000 mm along the combined gaze ray. `Gaze2D.gaze` is the projection of this point into the scene camera image. It is valid only when the combined origin and the combined direction are both valid.|

Each value field has a validity field: `gaze_origin_combined_valid`, `gaze_direction_combined_valid`, and `convergence_point_valid`.



<a id="eye"></a>

##### Eye

Used by `Gaze3D.left` and `Gaze3D.right`.

|Field|Type|Unit|Description|
|-|-|-|-|
|`gaze_origin_mm`|Point3D|mm|Gaze origin of the eye.|
|`gaze_direction_normalized`|Vector3D|unit vector|Gaze direction of the eye.|
|`pupil_diameter_mm`|float|mm|Pupil diameter.|
|`blink`|optional bool|-|`true` when the eye tracker detects a blink.|

Each value field has a validity field: `gaze_origin_valid`, `gaze_direction_valid`, `pupil_diameter_valid`, and `blink_valid`. `blink_valid` is also optional.

<a id="scenecameradata"></a>

##### SceneCameraData

File: `scenecameradata.pb.gz`. Auto-exposure settings of the scene camera. There is not one message for each video frame.

|Field|Type|Unit|Description|
|-|-|-|-|
|`timestamp_us`|int64|µs|Estimated recording time of the first video frame that uses these settings. It is 100 ms after the glasses read the settings.|
|`integration_time_us`|uint32|µs|Sensor integration time.|
|`analog_sensor_gain`|float|multiplier|Analog gain of the sensor. `1.0` is no gain.|
|`digital_sensor_gain`|float|multiplier|Digital gain of the sensor. `1.0` is no gain.|
|`digital_isp_gain`|float|multiplier|Digital gain of the image signal processor (ISP). `1.0` is no gain.|



<a id="glassesevent"></a>

##### GlassesEvent

File: `glassesevents.pb.gz`. Each message holds one event type in the `event` field, a protobuf `oneof`. Use `WhichOneof("event")` to get the name of the event type.

|Field|Type|Unit|Description|
|-|-|-|-|
|`timestamp_us`|int64|µs|Time of the event.|
|`event`|oneof|-|One of the event types below.|

|Event|Message|When the application writes it|
|-|-|-|
|`collecting_started`|`EventCollectingStarted`|Once, at the first saved scene video frame. The message has no fields.|
|`collecting_stopped`|`EventCollectingStopped`|Once, when the recording stops. The message has no fields.|
|`frame_dropped`|[`EventFrameDropped`](#eventframedropped)|When the gap between two scene video frames is 1.1 frame intervals or more.|
|`gaze_dropped`|[`EventGazeDropped`](#eventgazedropped)|When the gap between two gaze samples is more than one sample interval plus 2 ms.|
|`hardware_status`|`EventHardwareStatus`|Diagnostic. Every 10 seconds, with temperatures, power, and memory.|
|`notification`|`EventNotification`|Diagnostic. When a hardware value is out of range, or when a data stream stops.|
|`video_file_health`|`EventVideoFileHealth`|Diagnostic. Once, after the application closes the video file, with the result of a file check.|

The fields of the diagnostic events are in `glassesdata.proto`.



<a id="eventframedropped"></a>

##### EventFrameDropped

All timestamps in this event, including the `GlassesEvent.timestamp_us` of the event, are on the MP4 timeline. Zero is the first saved scene video frame.

|Field|Type|Unit|Description|
|-|-|-|-|
|`last_frame_number`|int32|-|1-based number of the first scene video frame after the gap. The number of frames saved before the gap is `last_frame_number - 1`.|
|`last_frame_timestamp_us`|int64|µs|MP4 time of the last frame before the gap.|
|`current_frame_timestamp_us`|int64|µs|MP4 time of the first frame after the gap.|
|`info`|string|-|Human-readable description.|



<a id="eventgazedropped"></a>

##### EventGazeDropped

|Field|Type|Unit|Description|
|-|-|-|-|
|`sample_count`|int32|-|Total number of gaze samples in the recording up to this event. It is not the number of missing samples.|
|`last_sample_timestamp_us`|int64|µs|Recording time of the last sample before the gap.|
|`current_sample_timestamp_us`|int64|µs|Recording time of the first sample after the gap.|
|`info`|string|-|Human-readable description.|



<a id="utctimemapping"></a>

##### UtcTimeMapping

File: `utcmapping.pb.gz`. Two messages: one from when the recording starts, and one from when it stops.

|Field|Type|Unit|Description|
|-|-|-|-|
|`timestamp_us`|int64|µs|Recording time.|
|`utc_unix_epoch_us`|int64|µs|UTC time at `timestamp_us`, as microseconds since the Unix epoch.|



<a id="geographicalcoordinates"></a>

##### GeographicalCoordinates

File: `geographiccoordinates.pb.gz`. Location of the device that runs the Glasses X application, from the Android location service. The application requests one sample per second. The device can send fewer, and the file is empty when location is not available.

An accuracy value of `0` means that the accuracy is unknown.

|Field|Type|Unit|Description|
|-|-|-|-|
|`timestamp_us`|int64|µs|Recording time of the sample.|
|`latitude`|double|degrees|Latitude, from -90.0 to +90.0.|
|`longitude`|double|degrees|Longitude, from -180.0 to +180.0.|
|`location_accuracy`|float|m|Estimated horizontal accuracy.|
|`altitude`|double|m|Altitude above the WGS84 ellipsoid.|
|`altitude_accuracy`|float|m|Estimated altitude accuracy.|
|`speed`|float|m/s|Speed.|
|`speed_accuracy`|float|m/s|Estimated speed accuracy.|
|`bearing`|float|degrees|Bearing, from 0 to 360.0.|
|`bearing_accuracy`|float|degrees|Estimated bearing accuracy.|
